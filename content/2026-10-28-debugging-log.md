> 작성 구조를 보여주는 예시입니다. 실제 회사에서 발생한 사건을 기술한 글이 아닙니다.

## 현상

예상한 동작과 실제 동작을 나누어 적습니다. 재현 조건과 오류 메시지를 함께 남기면 미래의 내가 상황을 이해하기 쉽습니다.

## 가설과 확인

| 가설 | 확인 방법 | 결과 |
| --- | --- | --- |
| 요청 주소가 잘못됐을 수 있다 | 요청 URL과 명세 비교 | 실제 점검 후 작성 |
| 입력 형식이 다를 수 있다 | 요청 본문과 API 명세 비교 | 실제 점검 후 작성 |

## 해결과 검증

어떤 변경을 했는지, 왜 효과가 있었는지, 같은 조건에서 다시 확인했는지를 기록합니다.

## 배운 점

해결 명령만 남기는 것보다 **판단의 근거**를 함께 남기면 비슷한 문제를 만났을 때 재사용하기 좋습니다.
